# Piece authoring and generation

Goal: the game's pieces can be written by a human, generated by code, or composed by an AI agent, all through one pipeline and one validator. Pieces are original, short, and matched to the student's current reading level.

The pipeline: write or generate `piece.abc` and `piece.meta.json`, run `npm run piece:lint` until it is clean, look and listen in `npm run piece:preview` (or on the review board, `npm run piece:board`, from a phone), and a human approves. Only approved pieces reach a production build.

## Ways to create pieces

1. **By hand:** write ABC and meta (au01, au02), run `piece:lint`, `piece:preview`.
2. **Programmatic generators** (`npm run piece:generate`, au06): five generators make draft pieces from a level and a seed; the same seed gives the same piece.
3. **AI-composed (agent loop)** (au07): an agent writes ABC and meta from a repeatable prompt, and the linter drives the fix loop until it is clean. The piece stays `draft`.
4. **In the game's editor** (after the MVP, `docs/features/ft_1_02-piece-editor.md`; preliminary, in the menu as Make, ft_1_02a): click notes onto the staff. The editor writes the same ABC and meta and runs the same check; own pieces get licence `NaN` and stay on the device.
5. **Import** (after the MVP, `docs/features/ft_Y_04-piece-import.md`): MusicXML, then MIDI, converted to ABC plus a draft meta file, so the same compiler, linter, preview and approval gate apply.
